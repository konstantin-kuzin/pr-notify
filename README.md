# PR Notify

## Назначение

**PR Notify** — расширение для **Google Chrome**, которое показывает **pull request’ы** в **репозитории Azure DevOps**:

- вкладка **Review** — PR на ревью (лично и/или через выбранные **reviewer-группы**);
- вкладка **My PRs** — ваши PR: **активные** и ниже **Complete** (по 10 с «Показать ещё»);
- в списках — проблемы **Policies** (Required и Optional) и информация о **конфликтах** слияния.


## Загрузка и установка

### 1) Загрузка проекта с GitHub

1. Установите Git, если он ещё не установлен:

2. Откройте терминал в папке, где хотите хранить проект и клонируйте репозиторий:
   ```bash
   git clone https://github.com/konstantin-kuzin/pr-notify.git
   ```


### 2) Установка расширения в Chrome

1. Откройте Chrome и перейдите на страницу:
   ```text
   chrome://extensions
   ```
2. Включите переключатель **«Режим разработчика»** (обычно справа сверху).
3. Нажмите **«Загрузить распакованное расширение»**.
4. Выберите папку проекта `pr-notify` (ту, где лежит `manifest.json`).
5. Убедитесь, что карточка расширения появилась в списке и включена.
6. Закрепите расширение на панели (иконка пазла → pin), чтобы быстро открывать popup.

### 3) Обновление установленной локальной версии

- Чтобы получить новые изменения из GitHub, откройте терминал в папке проекта и выполните:
  ```bash
  git fetch origin
  git pull origin main
  ```

- После обновления кода нажмите **«Обновить»** на `chrome://extensions` (или иконку перезагрузки на карточке расширения), чтобы Chrome перечитал файлы.

## Первоначальная настройка

Откройте страницу настроек: ссылка **«Настройки подключения»** внизу popup или **Параметры расширения** в Chrome.

### 1. Адрес коллекции (корень API)

В поле **«Коллекция»** укажите базовый URL, с которого строятся запросы `_apis/...`:

- **Azure DevOps Server / TFS:** `https://<сервер>/tfs/<имя_коллекции>` (часто совпадает с префиксом URL в браузере при открытии проекта).
- **Облако:** `https://dev.azure.com/<организация>`.

### 2. Проект и репозиторий

- **Проект** — имя team project, как в ADO.
- **Репозиторий (имя или GUID)** — Git-репозиторий, по которому нужен список PR (имя из веб-интерфейса или идентификатор).

### 3. Reviewer-группы

1. В поле поиска введите **полное отображаемое имя группы** (как в ADO), например `Hexa UI Design Review`.
2. Ниже отображаются **уже сохранённые** группы; ненужную можно **удалить** кнопкой **×**.

Если **список групп пуст**, при отборе PR учитываются **все** автоматически определяемые reviewer-группы вашего пользователя **и** PR с **личным** назначением вам. Если в списке есть хотя бы одна группа — в набор ревьюеров входят **только вы** и **эти** группы (подробнее — [docs/documentation.md](docs/documentation.md)).


### Версия API и авторизация

- **`apiVersion`** в интерфейсе **не задаётся**; значение по умолчанию — в [`ado-config.mjs`](ado-config.mjs) (для on-prem часто `6.0-preview`; для `dev.azure.com` при необходимости — `7.1` в коде или вручную в `chrome.storage.local` → `adoConfig`). Ориентируйтесь на текст ошибок в popup.
- **Вход:** по умолчанию **сессия браузера** (куки). 

## Поведение (кратко)

### Вкладки

- **Review** — активные PR на ревью (лично и/или через reviewer-группы); сортировка по ожиданию ревью и `updatedAt`.
- **My PRs** — ваши PR как автора:
  - сверху **активные** (с политиками Complete и конфликтами);
  - ниже **Complete** того же автора, по **10** штук; кнопка **«Показать ещё»** догружает следующую порцию;
  - счётчик на вкладке считает только активные.

### Policies (Required + Optional)

- Для активных PR на **Review** и **My PRs** запрашиваются policy evaluations (как блок Policies в ADO).
- Красные пункты **Required** → `blockingReasons`; красные **Optional** → `optionalPolicyReasons`.
- **Review:** розовый бейдж с числом замечаний → раскрываемый список (Required, затем Optional).
- **My PRs:** под карточкой список Required или **«Готов к Complete»**, плюс блок Optional при наличии; либо ошибка загрузки политик.
- У Complete на My PRs политики не показываются.

### Конфликты слияния

- Если `mergeStatus === conflicts`, запрашивается Conflicts API; в карточке — бейдж **«конфликт»**, клик раскрывает текст (сводка + пути файлов).
- На Complete в My PRs конфликты не загружаются.

### Прочее

- Автообновление активных списков **каждые 10 минут** (alarm) и при установке, старте браузера, смене конфига, ручном обновлении из popup.
- **Иконка и badge в панели Chrome:** по **максимальному рабочему возрасту** PR, **ожидающих ревью** (пн–пт, **10:00–18:00** МСК) — иконка обычная (≤8 ч), оранжевая (>8 ч), красная (>16 ч); **badge** (число PR) — серый (≤6 ч), жёлтый (>6 ч), оранжевый (>8 ч), красный (>16 ч). PR без новых пушей после комментария группы в расчёт не входят. При ошибке последнего запроса — иконка ошибки, badge пустой.
- При старте расширение **сверяет версию** с `main` на GitHub; если на GitHub новее — в popup появляется чип **«Новая версия — X.Y»** со ссылкой на репозиторий.
- Для каждого активного PR на **Review** дополнительно запрашивается **детальный PR** с `includeCommits=true`: **полное описание**, время **последнего пуша** source и (если настроены группы) **последний комментарий участника reviewer-группы**.
- **Сортировка Review:** PR с **ожиданием ревью** (новый пуш после комментария группы или комментария ещё не было) — **старые выше** по `updatedAt`; PR **без новых обновлений** после комментария группы — **в конце**.
- **Время в строке PR (Review):** от последнего пуша (или даты создания, если пуша нет); если после комментария группы новых пушей нет — **«Нет обновлений»**. При **> 6 / > 8 / > 16** рабочих ч (пн–пт, 10:00–18:00 МСК) — цветной **чип** (жёлтый / оранжевый / красный); пороги те же, что для срочности иконки.
- Описание в popup: **раскрываемая панель** с **упрощённым markdown** (в т.ч. заголовки h1–h6, ссылки, списки, картинки по http(s)).
- Для описаний с эвристикой «тех ПР» (только Review) — бейдж **ТЕХ ПР** и кнопка **Approve** (REST `vote: 10` для вашего identity), без автоматизации DOM.
- **Уведомления** о появлении новых id в списке Review (по сравнению с прошлым успешным обновлением).
- При ошибке API **последний успешный список в storage сохраняется** (поля ошибки и времени проверки обновляются).

## Какие PR попадают в список

### Review

- Статус **Active**, Draft = False
- В `reviewers` есть запись c `id` из набора: **вы** ∪ **группы из сохранённого списка** (или вы ∪ все reviewer-группы пользователя, если список групп в настройках **пуст**)
- Вы не голосовали за это ревью или ваш голос сброшен (**`vote === 0`**)

### My PRs

- **Активные:** статус Active, Draft = False, `creatorId` = текущий пользователь
- **Complete:** статус Completed, тот же создатель; догрузка постранично из popup (не в `prState`)

Подробное описание текущего поведения и полей данных: **[docs/documentation.md](docs/documentation.md)**.

## Устройство проекта

- [`manifest.json`](manifest.json) — MV3, `host_permissions` / `optional_host_permissions`
- [`background.mjs`](background.mjs) — расписание, обновление, badge, уведомления, approve
- [`ado-api.mjs`](ado-api.mjs) — HTTP к ADO, фильтрация, маппинг в модель UI
- [`ado-config.mjs`](ado-config.mjs) — ключ `adoConfig`, значения по умолчанию
- [`options.html`](options.html), [`options.css`](options.css), [`options.mjs`](options.mjs) — настройки
- [`popup.html`](popup.html), [`popup.css`](popup.css), [`popup.mjs`](popup.mjs) — список в popup
- [`working-time.mjs`](working-time.mjs) — рабочие часы (МСК), точка отсчёта, сортировка, пороги срочности

## Разрешения

- `alarms`, `storage`, `notifications` — см. манифест.
- Доступ к API ADO — `host_permissions` / optional для `dev.azure.com`.
- Проверка обновлений — `https://raw.githubusercontent.com/konstantin-kuzin/pr-notify/*` (манифест с GitHub).

## Ограничения

- Один проект и один репозиторий из настроек.
- Другой хост ADO может потребовать правки `host_permissions` в манифесте.
- Markdown в popup — упрощённый, не копирует рендер ADO целиком.
